# 绘梦 1.0 插件市场范围

> 现行需求：保留原版在线插件市场与已安装能力管理。M0-06 原版取证、M1 契约和前端适配已完成；后端及真实业务待 M2/M3。关联 [PRD FR-14](PRD.md)、[CONTRACTS §2.4](../api/CONTRACTS.md#24-插件市场与管理)、[TASKS](../plan/TASKS.md)。

## 1. 迁移范围

| 能力 | 1.0 处理 |
| --- | --- |
| 在线发现 | 保留搜索、分类、分页、卡片描述和版本展示；已安装技能保留说明/源码查看。不新增市场卡片详情接口或弹窗；管理员通过后端代理访问上游市场 |
| 收藏与“我的” | 保留原市场账号语义，使用公司统一账号；收藏修改限管理员，不新增员工个人市场账号系统 |
| 已安装 | 保留节点、工具、技能、文件扩展等列表、配置、启停、导出和原版允许的卸载；普通成员使用批准且启用的能力 |
| 安装与更新 | 管理员从市场安装或上传原版支持的本地文件；检查来源、文件、版本、冲突及运行占用；保留原版强制覆盖的明确确认 |
| Agent 包 | 固定提交 `agentMarketEnabled=false`，沿用关闭的市场安装状态；已有内部团队和 A2A 的既定范围继续保留 |
| Web 兼容 | 迁移可在 Web 使用的插件；依赖桌面浏览器等环境的能力仍按原 Web 范围处理，不能因为市场可安装就宣称可用 |
| 发布平台 | 复用原市场；不新增公司自己的公开插件发布、交易、结算系统。原“网页版市场/开发者文档”属于外部链接，需标明离开内部平台，不夹带凭据或项目数据 |

插件由平台统一安装，生效于允许使用它的项目；一期不新增项目专属插件版本或插件审批工作流。普通成员没有安装、改配置、改源码或启停权限；管理员启用即表示公司批准该能力。插件运行时的生成仍受项目授权与五名额限制，不能通过工具绕过。

## 3. 安全与部署要求

1. 市场和插件管理调用先经过 Spring 账号/管理员授权；不信任 `x-toonflow-workspace` 等客户端自报头。MCP/A2A 凭证无插件管理权限。
2. TF-Router 凭据和插件配置中的秘密字段由后端管理，不返回成员、不写日志、不随插件导出；原前端读取明文 settings 的做法必须替换。
3. 下载源经管理员配置允许，校验每跳重定向、DNS/地址、大小/超时、文件名/类型、归档路径、元数据及版本。公司获批的内网制品源可单独配置，不能开放任意内网 URL。
4. 安装清单记录类型、标识、版本、来源、摘要及启停状态，操作记录包含操作者和结果。更新失败保留现有可用版本；有运行占用时明确拒绝或等待安全时机后再变更。
5. 插件的脚本和服务端工具按可信代码管理，审查所用文件/网络能力并限制执行环境。市场描述、技能内容不能扩大成员权限或暴露其他项目与公司密钥。
6. 首次部署随发布清单安装必要内置插件和依赖，至少验证 Agent 可获取画布工具、查询媒体模型和调用画布。不能只以供应商列表和构建成功作为就绪证据。
7. 市场故障或未配置凭据时明确提示；已安装能力、本地文件安装及项目创作继续可用。局域网部署不等于服务器必须断网，在线市场依赖服务器可达上游目录与获批制品源。
