## 1. 当前决策基线

本页维护当前需求，不保留已被替代的方案。当前阶段和接手步骤见[交接入口](../handoff/README.md)；M0、M1 已完成，M2–M4 未开始，完整目标业务尚未验收。

本 PRD 描述**目标产品行为**，不表示功能已经实现。已确认：独立内部账号；仅平台管理员、项目成员；公司统一管理供应商 API Key；每项目最多 5 个同时执行的图片、视频、音频或 Agent 生成任务；无现成项目需要批量导入；不需要桌面端、移动端或实时共同编辑；保留并安全迁移原版插件市场；平台仅需在公司局域网可访问，MCP/A2A 面向局域网内获授权的客户端开放。详细上游路由与 A01–A18 验收编号见[迁移清单](TOONFLOW_WEB_MIGRATION.md)。

## 2. 背景、问题与目标

Toonflow 已具备 Web 画布、项目文件、素材、模型生成、Agent 和媒体处理能力，但当前运行形态以单人本地工作区和进程级配置为中心。公司要让多名内部制作人员在同一平台使用这些能力，需要先解决身份、项目隔离、统一密钥、外部调用授权、并发写入和执行服务暴露问题。

**1.0 目标**：将原有 Web 创作主流程安全迁移到独立部署的前端与 Spring Boot 对外后端，在明确的 Web 范围内保持功能、项目文件格式和创作结果兼容；五名员工可同时使用一个项目，保存冲突可见；获授权外部客户端可通过 MCP/A2A 使用被许可的项目能力。

**成功判定**：A01–A18 全部通过；被排除的入口不在 UI 或公开 API 中出现；关键流式响应与项目文件兼容性通过基线回归。偏离原 Web 流程的行为须写入版本变更记录并由业务方确认。

## 3. 产品范围

| 纳入 1.0 | 明确排除 |
| --- | --- |
| 内部账号、项目及成员权限；Web 画布、剧本、角色、场景、素材与项目文件；文本、图片、视频、音频生成；Agent 与画布控制；FFmpeg；插件市场（在线发现、搜索、收藏与已安装能力管理）、内置及获批第三方节点/工具/技能/扩展/Agent 包；管理员统一模型配置；MCP/A2A 对外授权入口 | 桌面端、移动端、设备互联、本机目录选择/定位；实时共同编辑；评论、审批、编辑占用、历史版本中心；旧项目批量导入；新增任务队列或独立任务中心 |

“功能保持不变”指纳入范围的**创作操作、可见结果、文件格式及事件语义**等价。为安全上线必须改变的入口包括登录、项目选择、权限提示、密钥配置和冲突提示。现有 Web 中依赖桌面环境的浏览器工具入口应隐藏，不能留下无效按钮。

## 4. 用户、场景与权限

| 角色 | 主要任务 | 权限边界 |
| --- | --- | --- |
| 平台管理员 | 创建/停用账号，建立项目和成员关系，维护供应商密钥与获批能力，签发/撤销外部客户端凭证，查看必要操作记录 | 可管理平台配置和项目元数据；访问创作内容仍需项目成员身份，高权限管理操作留审计 |
| 项目成员 | 在获授权项目中创作、保存、上传素材、运行生成与 Agent、导出成果 | 无权查看其他项目、供应商密钥、平台配置或高权限安装接口 |
| 外部 MCP/A2A 客户端 | 使用管理员授予的项目、工具和团队能力 | 使用独立可撤销凭证；不能使用员工会话，不能指定任意服务器目录或跨项目读取任务 |

一个项目可有超过 5 名成员；“5 人同时参与”是容量验收目标，不是成员数量上限。1.0 没有只读角色。由管理员开通内部账号，不开放公众注册。

## 5. 核心使用流程

1. 管理员建立账号与项目，分配项目成员，配置公司允许的供应商和模型。
2. 成员登录 Web，仅看到自己加入的项目；选择项目后进入既有创作界面。
3. 成员编辑画布、剧本及素材，保存时提交读取时的修订号。若他人先保存，界面提示冲突并允许重新读取、人工处理后再次保存，不静默覆盖。
4. 成员运行文本、媒体生成或 Agent，看到原有进度、事件、取消与结果；生成物归属当前项目。
5. 成员完成素材处理、FFmpeg 合成或导出；仅有权限的人可以访问结果文件。
6. 管理员签发限定到项目及能力的外部凭证；MCP/A2A 客户端通过统一 HTTPS 入口调用、查询或取消属于它的任务。

## 6. 功能需求

| ID | 需求 | 验收重点 |
| --- | --- | --- |
| FR-01 | 内部账号登录、退出、停用与登录限速 | 停用和退出阻断后续请求；不公开注册 |
| FR-02 | 管理员创建项目、管理成员；成员只看到和操作获授权项目 | 列表、文件、下载和外部接口均隔离 |
| FR-03 | 画布、剧本、角色、场景及原项目格式保持可读写 | 使用上游样例与新建样例验证打开、保存、再打开 |
| FR-04 | 文件/素材上传、复制、重命名、删除、读取与下载 | 不接受浏览器指定的服务器绝对路径；失败残留可识别清理 |
| FR-05 | 保存冲突检测 | 旧修订号写入返回冲突；原内容不被覆盖 |
| FR-06 | 保留文本、图片、视频、音频生成的模型选择、提交、进度、结果与取消 | 事件顺序和成功/失败语义与原 Web 一致 |
| FR-07 | 保留项目 Agent、单 Agent、问答、画布控制及内置能力 | 项目会话与发起人绑定；流式事件与回调可用 |
| FR-08 | 保留 FFmpeg 转码/合成、进度、取消和导出 | 资源超时、取消后释放，结果只属于授权项目 |
| FR-09 | 管理员维护供应商密钥、获批模型和内置能力；成员只可选择获批模型 | 密钥只写不回显，不在日志或导出物出现 |
| FR-10 | MCP/A2A 向获授权外部客户端开放 | 凭证可签发、限定、撤销；工具、团队、任务绑定项目与调用方 |
| FR-11 | 每项目生成并发上限 5 | Web、MCP、A2A 共用名额；第 6 个立即拒绝，不调用供应商 |
| FR-12 | 为关键配置、成员变更、凭证及高权限操作留必要审计 | 可按操作者、项目、操作和时间追踪 |
| FR-13 | Web 移除不适用入口 | 页面网络记录没有被排除路由的失败调用 |
| FR-14 | 迁移原版插件市场：在线发现、搜索、分类/分页、卡片描述与版本、收藏、已安装列表及管理员安装/更新、配置、启停、导出和卸载 | 公司统一凭据；成员只能使用获批能力；安装前后 Agent 工具实际可用；详见[市场范围](PLUGIN_MARKET.md) |

### 6.1 插件市场

插件按平台统一安装和管理，成员使用已批准且启用的能力。管理员保留在线市场和本地文件安装、现有配置与版本管理操作；市场凭据与模型 Key 均由后端管理。市场故障不阻断已安装能力。固定提交中关闭的 Agent 市场安装入口沿用原状态，不借本次范围调整提前开放。详见[范围与补验](PLUGIN_MARKET.md)；管理员和成员的按钮及服务端权限都须验证。

### 6.2 生成名额的精确定义

占用名额：项目内图片、视频、音频生成及一次项目 Agent 运行；A2A Agent 同样占用。Agent 内部触发的媒体生成不重复占用。仅文本生成不占这 5 个名额，但按账号或客户端限速。上游无项目目录的独立单 Agent 若从项目内调用，先绑定项目并占位；项目外调用按账号限流。名额在开始执行时占用，在成功、失败或执行服务**确认取消**后释放；浏览器断线本身不表示上游停止。第 6 个请求不排队。

当前测试基线：文本/Agent 使用公司统一管理的 DeepSeek API；媒体生成测试使用本地 ComfyUI。独立音频暂不配置本地供应商，沿用 Toonflow 默认供应商配置，本轮不执行独立音频生成成功流测试；音频接口、权限和并发计数仍按原设计保留。H3 视频自带声音不计作独立音频测试。当前本地供应商以[现用清单](../validation/LOCAL_PROVIDERS.md)为准：h3Local3060 2.0.0（5 模型）、qwenImage21Local 1.0.0（2 模型）；供应商替换后分别确认源码和模型标识，历史测试不自动转移。现用 Qwen 两模型的 1K 成功流已独立补测，M0 已收尾，见[最终记录](../validation/M0_FINAL.md)；多人权限与任务管理仍按 1.0 验收。

## 7. 页面与交互要求

1. 登录页、项目选择页和必要的管理员页面是 1.0 新增页面；管理员页面覆盖账号、项目成员、供应商配置、外部凭证、插件市场及已安装能力配置。
2. 原创作页面尽量维持交互与视觉习惯；仅替换项目入口、统一错误提示、保存冲突提示和无效桌面入口。
3. 成员看不到密钥值、外部凭证原文及高权限配置入口；服务端仍必须拒绝越权请求。
4. 外部凭证仅在创建时展示一次原文；管理员能看到标识、授权范围、创建时间和撤销状态。
5. 任务达到上限、项目无权限、会话失效、文件冲突和执行服务重启应有能让用户采取下一步动作的提示。

## 8. 数据与兼容要求

关系数据保存账号、项目、成员、外部授权、生成运行记录和必要审计。原画布 JSON、素材、Agent 会话及导出物继续使用受控项目工作区与原文件结构；一期不要求对象存储。项目 ID 在服务端映射到工作区目录，任何外部请求都不能把绝对路径当作授权凭据。没有现成业务项目，不开发批量搬迁；仍须用上游样例做读写兼容测试。

## 9. 非功能需求

| 维度 | 1.0 要求 |
| --- | --- |
| 安全 | 局域网入口统一 HTTPS；安全 Cookie、请求防伪、外部凭证哈希存储与撤销；路径规范化与逐次授权；Bun 不对外暴露 |
| 稳定性 | 流式连接、取消、断线与执行服务重启后状态清晰；任务不误报完成；工作区可备份和恢复 |
| 容量 | 同项目 5 人同时使用；每项目 5 个计名额任务；不同项目分别计数。首轮使用本地部署的 ComfyUI 进行生成及并发测试，记录实际响应耗时、失败率与资源占用；不预设脱离测试环境的数值阈值 |
| 可观测性 | 关联请求 ID、项目、用户/客户端和任务；记录状态与耗时；日志脱敏 |
| 可维护性 | 前端可独立构建、部署；契约与上游固定提交可追溯；Spring/Bun 分工明确 |

## 10. 业务规则与异常

| 情况 | 目标行为 |
| --- | --- |
| 非成员访问项目 | 拒绝；项目列表不泄露无权项目 |
| 旧修订号保存 | 返回冲突与当前修订号；原内容不得被覆盖 |
| 第 6 个并发生成 | 返回 `PROJECT_CAPACITY_EXCEEDED`；不启动实际执行 |
| 用户断线后任务继续 | 后端仍保有名额和可查询状态；完成、失败或确认取消后释放 |
| 供应商失败或超时 | 展示原有失败语义；记录失败，释放资源和名额 |
| 外部凭证撤销 | 新请求立即拒绝；进行中的执行按运维策略终止并记录 |
| Bun 重启导致内存任务失效 | 返回明确的失效/可重试状态，不误报成功 |

## 11. 依赖与风险

- 上游固定提交及其许可证、第三方依赖和内置插件来源必须可追溯。
- Spring 与 Bun 之间需要稳定的项目上下文、服务身份及流式转发；任何直连 Bun 的旁路都会破坏权限与并发控制。
- 上游进程内文件锁及 A2A 任务状态决定 1.0 先按**单 Bun 实例**部署；扩容前需改造锁与任务持久化。
- 模型供应商费用、可用性和服务协议由公司统一管理；首轮生成测试使用已有本地 ComfyUI，具体地址与工作流需在测试时核实。其他已启用适配器可用可控响应验证接口兼容；不要求接入远程媒体供应商或增加独立音频成功流测试。
- 服务器规范记录了局域网主机 `192.168.1.102`、现有 MySQL/Redis 与应用目录约定；部署前核实当前状态、端口和 ComfyUI 连通性，不把规范中的历史记录当作实时探测结果。

## 12. 验收与发布门槛

以[迁移清单 §6](TOONFLOW_WEB_MIGRATION.md#6-一期验收矩阵)的 A01–A18 为验收主表。发布前必须完成账号/权限/项目隔离，原项目格式与主流程，保存冲突，文本及媒体生成，Agent 与 FFmpeg，密钥脱敏，插件市场及内置能力，MCP/A2A 外部授权，Web 入口清理，备份回滚，每项目 5 名额及跨入口并发，断线重启处理。缺陷逐项关联 A 编号；全部通过后记录发布结果。

## 13. 版本边界与后续候选

1.0 只完成安全迁移与等价运行。后续可单独评估创作流程优化、对象存储、多实例执行、任务持久化和公司特色能力；这些候选不构成 1.0 隐含需求。画布实时共同编辑不在当前规划内。
